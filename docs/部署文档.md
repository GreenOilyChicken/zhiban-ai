## 1. 系统概览

知伴AI 是面向政务、银发康养、文旅三个方向的 AI 智能体全栈系统，由四个服务组成，通过 Docker Compose 一键编排：

```
Vue3 Web ──┐
           ├─► Java Spring Boot (:8080/api) ──HTTP──► Python 智能体 (:8081/api/v1)
微信小程序 ─┘         │                                       │
                   MySQL 8                             ChromaDB + BGE
```

| 服务 | 技术栈 | 容器端口 | 职责 |
|------|--------|----------|------|
| **MySQL** | 8.0 | 3306 | 主数据库 |
| **Python AI** | LangChain 0.3 + ChromaDB + BGE | 8081 | 对话 / 工具调用 / RAG / 语音 |
| **Java 后端** | Spring Boot 3.2 + MyBatis-Plus + JWT | 8080 | 业务与鉴权 |
| **Vue 前端** | Vue 3 + Element Plus + Nginx | 80 | 用户端 + 管理端 + 反向代理 |

Java 只负责业务与鉴权，AI 能力全部在 Python 侧，通过 `AI_SERVICE_URL` 调用。前端 Nginx 将 `/api/` 反向代理到 Java 后端，统一对外入口。

## 3. 快速部署

### 3.1 获取代码

```bash
git clone <仓库地址> zhiban-ai
cd zhiban-ai
```

### 3.2 配置环境变量

```bash
cp .env.docker.example .env.docker
vi .env.docker
```

按 [§4 环境变量配置](#4-环境变量配置) 填写必填项，尤其是 **API Key** 和 **数据库密码**。

### 3.3 一键启动

```bash
./start.sh
# 或手动执行：
# docker compose --env-file .env.docker up -d --build
```

首次构建需 5–10 分钟（拉取基础镜像 + Maven 构建 + npm install + 下载 BGE 模型）。

### 3.4 启动后的访问地址

| 服务 | 地址 |
|------|------|
| 前端 | http://服务器IP |
| 后端 API | http://服务器IP:8080/api |
| RAG 服务 | http://服务器IP:8081/api/v1/health |
| MySQL | 服务器IP:3306 |

默认管理员账号：`admin / admin123`（首次登录后请立即修改）。

## 4. 环境变量配置

所有配置集中在 `.env.docker` 文件中。复制 `.env.docker.example` 后按需修改。

### 4.1 必填项

| 变量 | 说明 | 生成方式 |
|------|------|----------|
| `DB_PASSWORD` | MySQL root 密码 | `openssl rand -base64 32` |
| `JWT_SECRET` | JWT 签名密钥（≥32 字符） | `openssl rand -base64 32` |
| `DEEPSEEK_API_KEY` | DeepSeek API Key | https://platform.deepseek.com/api_keys |

> ⚠️ 后端对 `DB_PASSWORD` 和 `JWT_SECRET` 采用**无默认值**安全设计——未注入则启动失败，避免弱口令上线。

### 4.2 敏感数据加密（推荐填写）

| 变量 | 说明 | 生成方式 |
|------|------|----------|
| `PHONE_ENC_KEY` | 手机号 AES-256-GCM 加密密钥 | `openssl rand -base64 32` |
| `PHONE_INDEX_KEY` | 手机号盲索引 HMAC 密钥 | `openssl rand -base64 32` |

留空则手机号明文存储并打印告警（仅限开发环境，生产环境务必注入）。

### 4.3 LLM 大模型配置

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `LLM_PROVIDER` | `deepseek` | `deepseek` / `openai` / `qwen` |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com/v1` | |
| `DEEPSEEK_MODEL` | `deepseek-chat` | |
| `OPENAI_*` | — | 切换到 `openai` 时填写 |
| `QWEN_*` | — | 切换到 `qwen` 时填写 |
| `LLM_TEMPERATURE` | `0.3` | 生成温度 |
| `LLM_MAX_TOKENS` | `2048` | 单次最大 token |

### 4.4 Embedding / RAG

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `EMBEDDING_PROVIDER` | `bge` | 生产用 `bge`；离线兜底 `hash`（仅链路验证） |
| `BGE_MODEL_NAME` | `BAAI/bge-small-zh-v1.5` | HuggingFace 模型名 |
| `EMBEDDING_DEVICE` | `cpu` | 有 GPU 改为 `cuda` 加速 |
| `RAG_API_KEY` | 空 | RAG 服务认证（可选） |

### 4.5 接口限流

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `RATE_LIMIT_ENABLED` | `true` | 是否启用限流 |
| `RATE_LIMIT_MAX` | `300` | 每窗口最大请求数 |
| `RATE_LIMIT_WINDOW_MS` | `60000` | 窗口大小（毫秒） |

### 4.6 语音（TTS/ASR，可选）

留空则使用内置 `edge-tts` / `whisper`；配置后走阿里云 NLS：

| 变量 | 说明 |
|------|------|
| `ALIYUN_ACCESS_KEY_ID` | 阿里云 AccessKey |
| `ALIYUN_ACCESS_KEY_SECRET` | 阿里云 Secret |
| `ALIYUN_NLS_APP_KEY` | NLS 应用 Key |
| `ALIYUN_NLS_TOKEN` | NLS 令牌 |
| `ASR_MODEL` | 语音识别模型：`tiny` / `base` / `small` / `medium` |

## 5. 部署后初始化

### 5.1 构建知识库（首次必须执行）

Python 服务首次启动会自动构建知识库（`KB_AUTO_BUILD=true`）。如需手动重建：

```bash
./start.sh init-kb
```

或分别构建三个方向的知识库：

```bash
docker exec zhiban-python-ai python elderly_agent/main.py --build-kb --rebuild
docker exec zhiban-python-ai python govpolicy_agent/main.py --build-kb --rebuild
docker exec zhiban-python-ai python tourism_agent/main.py --build-kb --rebuild
```

### 5.2 验证服务状态

```bash
# 健康检查
curl http://localhost:8081/api/v1/health
# 返回示例：{"status":"ok","llmProvider":"deepseek","collections":[...]}

# 查看容器状态
docker compose --env-file .env.docker ps
```

### 5.3 持久化卷

| 卷名 | 用途 |
|------|------|
| `zhiban-mysql-data` | MySQL 数据 |
| `zhiban-chroma-data` | ChromaDB 向量库 |
| `zhiban-hf-cache` | HuggingFace 模型缓存（避免重建容器重新下载 BGE） |

## 6. HTTPS / TLS 部署

### 6.1 设计说明

默认仅监听 80（HTTP），无需证书即可启动。生产环境需启用 443/TLS，通过叠加 [`docker-compose.https.yml`](../docker-compose.https.yml) 实现。

### 6.2 启用 HTTPS

**方式一：自签名证书（开发 / 内网 / 演示）**

```bash
bash scripts/gen-self-signed-cert.sh -d your-domain.com
```

**方式二：正式证书（生产环境）**

将 Let's Encrypt 或商业 CA 的证书放置为：
- `certs/server.crt`（证书文件）
- `certs/server.key`（私钥文件）

**启动 HTTPS：**

```bash
docker compose --env-file .env.docker \
  -f docker-compose.yml -f docker-compose.https.yml up -d
```

### 6.3 回到 HTTP-only

```bash
docker compose --env-file .env.docker \
  -f docker-compose.yml -f docker-compose.https.yml down
docker compose --env-file .env.docker up -d
```

> ⚠️ 自签名证书会被微信小程序判定为不受信任，生产环境必须使用受信任证书（Let's Encrypt 或商业 CA）。

## 7. 微信小程序配置

### 7.1 配置后端地址

编辑 `wechat-miniprogram/app.js`，将 `apiBaseUrl` 改为生产域名：

```js
globalData: {
  apiBaseUrl: 'https://your-domain.com/api',  // 生产必须 HTTPS
```

### 7.2 开发与调试

用微信开发者工具打开 `wechat-miniprogram/` 目录，修改 `apiBaseUrl` 指向本地或测试后端即可调试。

在微信公众平台提交审核，并在后台配置 request 合法域名白名单。

## 8. 运维操作

### 8.1 常用命令

```bash
./start.sh              # 启动（默认 Docker 模式）
./start.sh status        # 查看容器状态
./start.sh logs          # 查看所有服务日志
./start.sh logs java     # 查看指定服务日志
./start.sh stop          # 停止所有服务
./start.sh build         # 仅构建镜像
./start.sh init-kb       # 重建知识库
./start.sh clean         # 停止并删除所有容器和卷（⚠️ 数据丢失）
```

### 8.2 更新部署

**更新代码后重新部署：**

```bash
git pull
./start.sh               # 会重新构建并启动
```

**修改环境变量后生效：**

```bash
vi .env.docker
./start.sh stop && ./start.sh
```

### 8.3 数据库管理

```bash
# 进入 MySQL 容器
docker exec -it zhiban-mysql mysql -uroot -p

# 查看数据库
SHOW DATABASES;
USE zhiban_ai;
SHOW TABLES;
```

### 8.4 备份与恢复

```bash
# 备份
docker exec zhiban-mysql mysqldump -uroot -p zhiban_ai > backup.sql

# 恢复
docker exec -i zhiban-mysql mysql -uroot -p zhiban_ai < backup.sql
```

向量库（ChromaDB）通过数据卷持久化，备份卷即可：

```bash
docker run --rm -v zhiban-chroma-data:/data -v $(pwd):/backup alpine \
  tar czf /backup/chroma-backup.tar.gz -C /data .
```

## 9. 健康检查与常见问题

### 9.1 健康端点

| 服务 | 地址 | 预期 |
|------|------|------|
| 前端 | `http://服务器IP/` | 200，返回首页 |
| Java 后端 | `http://服务器IP:8080/api/health` | 200 |
| Python AI | `http://服务器IP:8081/api/v1/health` | 200，返回 `llmProvider` + `collections` |

### 9.2 常见问题

**Java 启动失败：`DB_PASSWORD 必须通过 .env.docker 注入`**
→ `.env.docker` 里 `DB_PASSWORD` 为空。填入密码后重启。

**Python 启动后 LLM 调用 401**
→ 检查 `LLM_PROVIDER` 对应的 API Key 是否填写正确。

**首次启动很慢（Python 卡在下载 BGE 模型）**
→ 首次需从 HuggingFace 下载 `BAAI/bge-small-zh-v1.5`（约 100MB）。后续通过 `hf_cache` 卷缓存，重建容器不再重复下载。离线环境可临时设 `EMBEDDING_PROVIDER=hash` 先验通链路。

**前端 502 Bad Gateway**
→ Java 后端未启动。执行 `docker compose --env-file .env.docker ps` 确认 `zhiban-java-backend` 状态为 running。

**SSE 流式对话不流（一次性返回）**
→ 前端 Nginx 反代未关 buffer。确认 `vue-frontend/nginx.conf` 中 `location /api/` 段有 `proxy_buffering off;`。

**MySQL 连接被拒**
→ 确认 `DB_PASSWORD` 与 MySQL 容器初始化时一致。若修改密码需删除 `zhiban-mysql-data` 卷后重建。

### 9.3 查看日志

```bash
# 所有服务
./start.sh logs

# 指定服务
./start.sh logs java       # Java 后端
./start.sh logs python-ai  # Python AI
./start.sh logs mysql       # MySQL

# 直接用 docker 命令
docker compose --env-file .env.docker logs -f java-backend
```

## 10. 安全清单

### 10.1 部署前必做

- [ ] `DB_PASSWORD` / `JWT_SECRET` 使用 `openssl rand -base64 32` 生成强随机值
- [ ] `PHONE_ENC_KEY` / `PHONE_INDEX_KEY` 已注入（生产环境）
- [ ] `DEEPSEEK_API_KEY` 填写真实 Key
- [ ] 生产环境启用 HTTPS（使用受信任证书）
- [ ] `.env.docker` 文件权限设为 `chmod 600`，不提交到版本控制
- [ ] 服务器防火墙仅开放 80/443，3306/8080/8081 端口不对公网开放

### 10.2 已内置的安全设计

| 项 | 实现 |
|----|------|
| 密码存储 | BCrypt 加密 |
| 手机号存储 | AES-256-GCM 加密 + HMAC-SHA256 盲索引 |
| 认证 | JWT（24 小时过期，密钥环境变量注入，无默认值） |
| 接口限流 | 300 次/60 秒（可配置） |
| 安全响应头 | `X-Frame-Options` / `X-Content-Type-Options` / `X-XSS-Protection` |
| 文件上传限制 | 单文件 10MB / 总请求 12MB |
| 医疗安全 | 不给具体剂量 + DDI 药物相互作用检查 + 疾病-药物禁忌 + 免责声明 + 紧急信号识别 |

## 附录：启动顺序

```
MySQL ──► Python AI (8081) ──► Java 后端 (8080) ──► 前端 (80)
```

- Java `depends_on` MySQL healthy + Python started
- Python 独立启动，首次自动构建知识库
- 前端只依赖 Java 可达（Nginx 反代 `/api/`）
